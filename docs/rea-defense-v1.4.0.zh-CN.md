## 一、完整内容包含，补上只比较整个文件摘要的缺口

旧规则比较私有引用与整个公开 payload 的 SHA-256。源码前面加头部、后面加换行或与公开
模块串接后，整个文件的摘要发生变化，但私有实现仍完整存在。新规则保留原有整文件比较，
同时检查整个私有内容是否连续出现在更大的 payload 中。

对于长引用，先用最长 64 字节的定位锚寻找候选，再对原始长度的整个片段执行流式 SHA-256
验证。共同许可证、文件头或相同前缀本身不构成泄漏命中。1–64 字节引用按完整字节匹配，
不会为了速度跳过短引用；用户登记非常短的常见值时，普通公开文件也可能如实命中。

匹配器处理跨读取块、重叠候选、同锚不同长度和重复引用。它不导入、不执行、不反序列化
待检查代码。扫描、签名和最终验证继续复核私有输入，失败时清理本轮新创建的签名旁文件。
报告不给出外部引用路径、内容、定位锚或单独的私有摘要。

### 真实恢复与剩余边界

实验中的私有函数为公开自有样例，输入 `[-2, 0, 1, 11]` 得到 `[-55, 19, 56, 426]`。
每个 REA 报告必须有完整 graph、正确文件摘要、无跳过、无解析失败。实验使用 REA 返回的
绑定摘要的函数源码范围提取函数，生成独立模块执行，再比较原始、发布和恢复模块的四个结果。

**修改注释但保持函数行为的样本仍被放行，REA 也仍能恢复。** 这一反例保留在每份报告中。
它说明精确字节规则不识别语义等价实现；改写、编码、编译、分片和未登记的文件仍需其他
构建与架构措施。此版本没有把这个结果包装成“源码已不可逆向”。

### 有界资源成本

上限仍为 64 个引用、每个 8 MiB、合计 64 MiB。定位锚内容最多合计 4 KiB，这不是全部
进程内存承诺。整轮扫描共享 **4,096 个候选检查、512 MiB 候选验证读取**；在读取前预留
完整候选长度，超限则标记 `private_input_unverifiable` 和未完成状态，阻止发布。

| 本地资源控制 | npm 对照进程观察 | 含义 |
| --- | ---: | --- |
| 64 引用、256 MiB 普通公开数据 | 6.615 秒；matcher 追踪峰值 415,385 B | 0 候选、0 额外完整片段验证 |
| 1 引用、64 MiB 普通数据 | 0.044 秒 | 相同有界查找路径 |
| 密集假锚 | 4,096 候选后明确拒绝 | 没有把预算耗尽算作无泄漏 |
| 8 MiB 假候选反复校验 | 累计恰好 536,870,912 B 后拒绝 | 第 65 个候选不再读取完整片段；计数与已读取字节分别报告 |

这些是单机、单次、含 `tracemalloc` 开销的 helper 测量，运行期间也有其他验证工作。
追踪峰值不含预分配 fixture、解释器、scanner 元数据和容器 buffer，不能宣传为完整扫描
吞吐或总内存上限。第二套 REA 运行中的原始数值也保留在报告中。[完整范围](private-input-content.md)

## 二、字符串内的结构化密钥，按真实消费者验证

新增六种恢复输入：一层 JWK 字符串、两层 JWK 字符串、Unicode 转义的双层 JWK、一层已知
密钥数组、两层数组、整值浮点数组。Node 实际执行 `JSON.parse`，再调用 Ed25519 签名或
AES-256-GCM 解密；公钥验签或精确明文比较必须通过。官方基线对全部样本允许发布，候选
全部给出完成检查后的私钥结构或已知密钥命中。

每条路径最多额外两层 JSON 容器解码，单容器最多 64 KiB UTF-8 文本；所有分支与已有
DER/PEM 解码共享 64 候选、256 KiB 预算，节点与深度继续受 100,000 / 64 限制。
重复字段、非有限数值、第三层、单项超大、总字节超限、候选数超限的六个样本均仍可由
消费者恢复，但候选明确记为检查不完整并拒绝，不计入六个正面检出。

审查发现空对象/数组占位符也可能消耗预算，因此加入不需要 JSON 解析的确定为空判断。
260 个空容器继续通过，混入真实密钥仍会命中。非空公开容器仍要解析并消耗预算；例如
65 个非空序列化公开对象可因预算不足被拒绝。正常语料通过数量不能解释为任意 JSON 都兼容。

## 三、降低配置遗漏和排查成本

`project-init` 直接接受重复的 `--private-input-file`、`--asset-key-file`。输入先验证，
路径从 CWD 转为相对新 `project.json` 保存；写入后再次复核，失败清理新建目录。工作流
对照没有手工编辑 JSON，移动整个项目后换 CWD 执行检查，CLI 和真实 SDK 仍使用一条私有
文件及一条资产密钥引用。额外参数为空也不能清掉配置中的引用。

`--format text` 显示未配置、策略关闭、已完成和未完成四种不同情况，并提供固定诊断与
动作。动态路径、成员名和细节用 ASCII JSON 风格转义，避免换行、ESC 或 Bidi 控制字符
改变终端显示；私有引用、内容和独立摘要不进入报告。默认 JSON、退出码和 stdout/stderr
分工保持，`prepare` 旁文件仍为原有可验证 JSON。

一条完整副本 finding 从 74 行缩为 23 行，这是输出形态的测量，不是扫描速度或广义
可用性得分。README 同时保留默认机器协议和新可读入口，未配置的保护不再靠用户从长
JSON 中自行寻找零值。

## 回归、安装与复现

本地运行 **1,066 个 Python 用例：1,065 通过、1 个跳过**，另有 **10 个测试类在 setup
阶段跳过**；SDK **67/67**，真实 CLI 集成 **12/12**。unittest 汇总的 11 条 skip 记录
混合了用例和测试类，不能把 11 再从 1,066 中全部扣除。按同一日志口径，v1.3 有 1,000
个用例通过，本轮新增 65 个 Python 测试方法。跳过项包括本机缺失的 Java、macOS/MSVC 控制及 LLVM 18
转换插件；Linux 本地实际运行 LLVM 19 元数据控制，跨平台和 LLVM 18 必需对照留给原有
13 个 CI 作业。门禁严格检查真实完成状态，未把跳过算为成功。[验证记录](results/validation-v1.4.0-local.json)

新增行为也进入全新 wheel、sdist 和 SDK 安装验证。发布器对新增字段使用严格布尔检查，
缺失、false、数字 1 或字符串 `true` 均不能授权发布。安装中的包含样本长于 64 B，明确
核对完整内容验证读取，避免只证明短锚分支。

安装两个版本及固定 REA 依赖后，可运行：

```sh
node benchmarks/private_content_controls.mjs --python /trusted/candidate/python \
  --baseline-python /trusted/baseline/python \
  --baseline-wheel /trusted/open_release_guard-1.3.0-py3-none-any.whl \
  --out private-content-controls.json
python benchmarks/stringified_key_recovery.py --python /trusted/candidate/python \
  --baseline-python /trusted/baseline/python \
  --baseline-wheel /trusted/open_release_guard-1.3.0-py3-none-any.whl \
  --out stringified-key-recovery.json
python benchmarks/usability_controls.py --python /trusted/candidate/python \
  --baseline-python /trusted/baseline/python \
  --baseline-wheel /trusted/open_release_guard-1.3.0-py3-none-any.whl \
  --out usability-controls.json
```

第二套 REA 为第一个命令追加 `--rea-source` 与完整 `--rea-source-commit`。输出路径必须
是新文件。候选和基线包、SDK 发布文件、工具源码与运行时的身份核验记录在 JSON 内；
任一必需消费者不执行、分析不完整或身份变化都会让实验失败。版本迁移见
[v1.4 发布说明](releases/v1.4.0.md)，最终下载物的提交与哈希以 Release 附带证据为准。
