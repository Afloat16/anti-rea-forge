# REA 能力审阅与 v0.2 防护边界

本文面向保护自己软件的开发者，说明 Open Release Guard 的编译接入与
[REA 官方项目](https://github.com/morluto/rea) 的分析入口如何对应。
**这是官方文档与代码的只读能力审阅，不是运行 REA 后得到的对抗测试报告。**
本文不声明防破解成功率，也不保证客户端代码无法恢复或修改。

后续实际执行结果见 [2026-10-15 测试报告](testing-2026-10-15.zh-CN.md)：独立 Ghidra 和运行时恢复均成功，REA 整合流程受环境限制。下面的能力审阅与评估协议不替代该测试结论。

不能代表分析者无法改用其他 REA provider、原始字节或运行时观察继续调查。

## v0.2 的接入范围

编译保护 hook 面向 **CMake 构建的 C++17 工程**，按目标接入；具体函数、
选项和工具链要求以仓库 README 与 CMake 模块为准。它需要源代码及重新编译，
不能直接把任意现成 EXE/DLL 转换成受保护文件。

`RG_TEXT` 必须由开发者用于选择的字符串字面量。仅接入 hook 不会自动找到所有
敏感文字，不会自动改写整个程序的控制流，也不会把第三方依赖全部转换。
目前没有 .NET、Electron、JavaScript 或其他语言的自动转换 backend。
已有 EXE/DLL 检查、签名与授权功能也不等于这些语言的编译保护支持。

| v0.2 措施 | 对应的 REA 入口 | 能做什么 | 仍然成立的限制 |
| --- | --- | --- | --- |
| Release 优化与工具链支持的 LTO | 函数库存、调用关系、伪代码和跨函数追踪 | 减少未优化代码留下的结构和部分无用函数，使编译产物与源代码结构不再逐项对应 | REA 仍能分析优化后的机器码；性能优化没有通用的抗反编译效果保证 |
| 控制内部符号和调试资料的发布 | `list_names`、`list_procedures`、调试类型与名称证据 | 减少内部函数名、源路径与类型信息作为调查起点 | 按地址、导入 API、代码模式和行为仍可定位功能；已有公共导出仍是可见线索 |
| `constexpr` 生成的 `RG_TEXT` 静态文字掩码 | 字符串搜索及随后进行的引用定位 | 对开发者选中的字面量减少直接明文检索入口，并用最终产物检查验证是否残留 | 编译器可能重新物化明文；解码逻辑、掩码数据和构建种子不构成秘密；运行时明文可被观察 |
| 构建后的发布门禁 | 发布物中的明文、符号和调试资料入口 | 将已配置的发布要求变成检查失败，避免依赖开发者记忆 | 通过门禁只证明这些检查对该产物通过；不证明算法不可恢复、授权不可绕过或不存在其他泄露 |

DLL 的公共 ABI 由开发者维护。hook **不会自动隐藏或重命名公共导出**，
也不会推断哪些接口可以删除。修改导出、调用约定、结构体布局或依赖可见性前，
必须验证现有调用者仍可加载并调用 DLL。内部符号控制不能代替 ABI 设计。

`RG_TEXT` 的构建种子可以公开，也可能从产物与解码逻辑中推导出来。
更换种子可改变构建中的静态表示，不能使同一台不可信客户端拥有保密密钥。
不要把 API 私钥、签名私钥或需要长期保密的凭证放进 `RG_TEXT` 后分发。
Frida 等运行时工具仍可能观察解码后的文字、函数参数和结果。

`/GS`、CFG、DEP、ASLR 等措施主要针对内存利用，不应计入“阻止 REA 反编译”
的成果。代码签名和完整性检查可以发现未获签名的改动，但本地检查本身也可能被修改。

## 开源策略与私有发行密钥

保护工具的源码、文字掩码算法、构建参数和种子可以公开。应当假定分析者已经知道
这些内容，并能自己构建、阅读和修改本项目。开源带来的可审计性不依赖算法保密。

发行签名私钥与授权签发私钥应留在开发者或服务端受控环境，不能进入仓库、发布物、
构建日志或客户端。客户端可以包含用于验签的公钥；知道公钥不等于能产生有效签名。
测试用密钥只能用于测试，不能沿用为生产密钥。

签名证明的是内容由持有对应私钥的一方签发。它不能强迫被修改的客户端继续执行验签。
若业务需要可靠地限制付费能力或保护关键算法，最终权限判断或关键计算需要处在服务端
等开发者可控制的边界内。纯离线客户端没有同等的信任边界；应明确接受其可被分析与修改。
本项目开源也不要求使用本工具保护的业务源码、生产密钥或服务端实现一并公开。

## 可复现的 REA 评估协议

只有实际对照实验才能判断这些措施是否增加了指定任务的成本。下面是实验协议，
不是已经完成的测试或预估的成功率。

### 1. 固定环境与预算

每轮记录并保存：

- REA 的完整 commit、包版本、安装包摘要和启用的工具集合。
- provider 名称、完整版本、平台、架构、分析配置与超时。
- agent 版本、模型提供方、模型完整标识、可设置的采样参数，以及运行日期。
- 操作系统、编译器、链接器、CMake 与依赖版本、编译选项和完整构建日志。
- 每个任务的墙钟时间、工具调用次数、输入与输出 token、并发数和允许的人工介入。
- 是否允许动态运行、联网、Frida 及其他 provider；权限和输入在两组中保持一致。

若模型接口不能锁定权重或确定性，须写明这一复现限制，并保留逐次原始记录。
修改预算、工具可用性、模型或 provider 后应作为新一轮实验，不能混入同一个成功率。

### 2. 使用自有样例与随机多样本

建立允许分析和修改的 EXE/DLL 样例集，包含不同大小、算法、错误路径和授权状态。
为每个样例生成普通 Release 与保护后的配对构建，保留可核验的源代码与正确答案。
记录每个产物的 SHA-256 和随机种子；种子用于复现实验，不作为保密假设。

预先规定样本数量与停止规则，随机化构建种子、任务分配和呈现次序。
不能只选择对保护措施有利的样例，也不能在看到结果后删掉失败样例。
同一程序仅更换文字种子产生的多个产物不等于多个独立业务样本；统计时应按程序与任务
分组处理重复观测，避免夸大有效样本量。

### 3. 盲任务与独立评分

分析方只得到待发布文件、必要的运行条件与固定任务说明；不给源码、预期函数地址、
私有符号或答案。普通与保护构建使用相同权限和预算，随机使用中性样本编号。
允许分析方阅读本项目公开代码；保护效果不能建立在它不知道算法或种子的前提上。

| 任务 | 预先规定的成功判据 |
| --- | --- |
| 从已知界面文字或错误文字定位功能 | 能给出准确的函数或地址，以及与目标行为的证据关联；仅找到相似字符串不算完成 |
| 恢复指定算法 | 独立实现通过未提供给分析方的边界、随机和正常用例；伪代码看起来相似不算完成 |
| 对自有授权样例进行绕过评估 | 在无效或过期授权状态下，实际完成预先定义的受限操作，并能重复验证；改变界面提示不算完成 |
| 跨构建匹配功能 | 在保留的测试构建中正确匹配目标功能，同时报告误匹配；不能只展示成功的个例 |

成功、失败、超时和环境故障要分开记录。工具配置错误或不支持目标格式，不能计作
防护成功。评分方使用保留答案、功能测试和证据评分，不能只接受 agent 自述。

### 4. 同时验证可用性与成本

先验证普通和保护构建的功能输出一致，再进行对抗任务。至少覆盖：

- 正常、边界与错误输入，授权有效、无效、过期和离线场景。
- DLL 的导出集合、调用约定、数据布局，以及既有调用者的加载和调用结果。
- 启动时间、相关函数延迟、吞吐量、内存、产物体积和构建时间。
- 选中文字在最终发布物中的残留情况、未选中文字和私有调试资料的发布情况。
- 支持矩阵中每个声称支持的工具链和架构；未运行的组合明确列为未验证。

性能测量固定硬件、数据集、预热与重复次数，保存原始数据并预先规定可接受的回归阈值。
功能或 ABI 损坏不能视为保护有效。

### 5. 结果与概率表述

报告必须包含实际样本量、每项任务的成功与失败计数、预算、原始记录和置信区间。
独立二项任务可报告预算内成功率及 Wilson 95% 置信区间；存在配对、同程序重复任务
或多次模型运行时，应使用与分组结构相符的统计方法，并解释有效样本单位。
同时报告预算内完成时间与超时数量；超时是被预算截断的观测，不能直接当作成功耗时求平均。

置信区间只描述该样例集、工具配置和预算下的结果。即使某一轮没有成功破解，也不等于
不可破解，更不能推出所有 REA 版本、模型、人工分析者或无限预算下的安全概率。
在完成这类实验以前，只能陈述已经实现并验证的构建行为。

本协议不使用工具故障利用、破坏分析器、攻击载荷或针对 agent 的提示注入作为防护措施。
实验目标是测量合法软件保护的实际成本与边界。
