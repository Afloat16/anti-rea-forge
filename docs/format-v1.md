# v1 签名格式与接入约定

本文件定义当前 Python 实现的协议；跨语言实现需使用测试向量或互操作测试另外验证。本项目不提供原生运行时 SDK。

## 外层封装

UTF-8 JSON 对象，恰好包含以下四个字段，外层排版可不同：

| 字段 | 值 |
| --- | --- |
| `format` | `open-release-guard/v1` |
| `kind` | `manifest` 或 `license` |
| `payload` | 标准 Base64 编码的原始 payload 字节，含标准填充 |
| `signature` | 标准 Base64 编码的 64 字节 Ed25519 签名 |

没有公钥字段。验证调用方选择先前信任的 Ed25519 公钥；公钥保存为 PEM SubjectPublicKeyInfo，私钥为口令加密 PEM PKCS#8。

签名对象按字节拼接：ASCII `OpenReleaseGuard`、单字节 `0x00`、ASCII kind、单字节 `0x00`、ASCII `v1`、单字节 `0x00`、原始 payload 字节。使用 **Ed25519**，不是 Ed25519ph，也不先对 payload 做 SHA-256。清单内每个文件的内容单独计算 SHA-256。

## Payload 编码与校验顺序

签发器使用 Python `json.dumps(body, sort_keys=True, separators=(",", ":"), ensure_ascii=True, allow_nan=False).encode("ascii")`。这是本协议自己的编码约定，并非声称实现 RFC 8785。签名验证使用封装中解码得到的原始字节；不要先解析并重排字段再验签。验签成功后再解析并检查规范编码、字段和业务约束。

v1 仅使用字符串、整数、数组和对象；业务 schema 不接收浮点数、NaN 或 Infinity，整数类型不接受布尔值代替。拒绝任意层级重复 JSON 键、未知字段、未知版本及非规范 payload 排版。中文和其他非 ASCII 字符在 payload 中通过 JSON Unicode 转义表示，补充平面字符使用代理对。未配对代理字符不得作为业务文本或路径使用。严格跨语言验证器应按本协议重现编码后逐字节比较，或与当前 Python 实现建立互操作测试。

整份文档最大 8 MiB；解码后的 payload 最大 4 MiB。不要执行任何 payload 内容。

## 清单 schema

| 字段 | 类型与含义 |
| --- | --- |
| `version` | 整数 `1` |
| `product` | 非空字符串，最长 128 字符，必须匹配调用方预期 |
| `release` | 非空字符串，最长 128 字符，可与调用方固定版本匹配 |
| `created_at` | UTC 时间，精确为 `YYYY-MM-DDTHH:MM:SSZ` |
| `files` | 1–20,000 个文件记录，每个恰好包含 `path`、`size`、`sha256` |

`path` 是 NFC Unicode、以 `/` 分隔的受限相对路径。拒绝空路径组件、`.`、`..`、绝对路径、反斜线、冒号、Windows 非法字符和设备名、尾部点或空格、大小写折叠冲突。设备名检测覆盖扩展名前的空格及 `CONIN$`/`CONOUT$`。每组件最多 255 UTF-8 字节，总长度最多 1024 字符。`size` 是 0 到 2^63-1 的整数；`sha256` 是 64 位小写十六进制字符串。目录扫描最多接收 40,000 个文件与目录条目，其中普通文件最多 20,000 个。

验签后扫描调用方指定根目录，拒绝链接/reparse point 和非普通文件，严格比较完整文件集合，再逐个核对长度和哈希。目录中的日志或额外 DLL 都会失败。空目录不是清单签名对象；它们仍需通过路径和链接检查。对抗恶意并发文件替换需要可信安装目录、权限隔离或原生文件句柄/加载集成；单次清单校验不保证未来加载的文件仍相同。

## 许可证 schema

| 字段 | 类型与含义 |
| --- | --- |
| `version` | 整数 `1` |
| `product` | 非空字符串，最长 128 字符，必须匹配调用方预期 |
| `subject` | 非空字符串，最长 256 字符，可与调用方预期持有人匹配 |
| `license_id` | 规范小写、带连字符 UUID 字符串 |
| `issued_at`、`not_before`、`expires_at` | UTC 时间，格式同上 |
| `features` | 最多 128 个互不重复的功能标识符，每个匹配 `[A-Za-z0-9_.:-]{1,64}` |

需要 `issued_at <= not_before < expires_at`，并要求 `not_before <= 当前时间 < expires_at`。调用方所需功能必须是签名中授权功能的子集。签发 CLI 的有效期限制为 1–3650 天；这些限制不提供可靠离线时钟、许可证设备绑定、服务器撤销或持久防回滚功能。

客户端应固定产品、公钥和必要权限，并在每个受控业务入口执行策略。不能把“签名数学上有效”直接等同于“允许任意功能”。
